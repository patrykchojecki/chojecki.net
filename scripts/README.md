# Site maintenance

Run these commands from the repository root. See the [main README](../README.md) for toolchain setup and local development. This directory is excluded from Jekyll publishing.

## Build and deployment checks

```sh
npm run check
python3 scripts/prepare-cloudflare.py
npm run check:site
```

`npm run check` runs the OpenXBL tests, all Python regression tests, the JavaScript build, and the production Jekyll build with generated-site validation. Despite its historical name, `npm run test:seo` covers hosting, asset preparation, publication containment, and measurement tools as well as search metadata.

`prepare-cloudflare.py` adds HTTP redirects, content-hashed assets, caching headers, and stylesheet preload hints to `_site/`. It also checks upload limits and rejects runtime functions. Rebuild with `npm run build` to restore plain Jekyll output.

To check the published site independently:

```sh
npm run check:live
```

To compare a deployment with the exact prepared build that was uploaded:

```sh
npm run check:live -- --expected-dir _site
python3 scripts/check-hosting.py --base-url https://chojecki.net --site-dir _site --check-host-redirects
```

A fresh local build can differ from the deployed build, especially when Xbox data changes. Use the matching deployment artifact for exact comparisons. Preview checks and manual upload instructions are in the [Cloudflare runbook](cloudflare/README.md).

## GitHub Actions settings

| Setting | Kind | Purpose |
| --- | --- | --- |
| `CLOUDFLARE_ACCOUNT_ID` | Repository variable | Account owning the `chojecki-net` Pages project |
| `CLOUDFLARE_API_TOKEN` | Actions secret | Token scoped to Account → Cloudflare Pages → Edit for that account; no DNS access needed |
| `CLOUDFLARE_CUSTOM_DOMAIN_ACTIVE` | Repository variable | Set to `true` to verify `https://chojecki.net` after deployment |
| `OPENXBL_API_KEY` | Actions secret, optional | Fetch live Xbox activity before building |

The [Cloudflare workflow](../.github/workflows/cloudflare.yml) deploys on pushes to `master`, every six hours, and on manual dispatch. It verifies a preview before publishing the same files to production, then checks the Pages origin and configured custom domain. A failed post-deployment check does not automatically roll back the site; follow the [rollback procedure](cloudflare/README.md#rollback-procedure).

The [pull-request workflow](../.github/workflows/check.yml) runs validation and packaging without credentials or uploads. The [GitHub Pages workflow](../.github/workflows/static.yml) is manual rollback only. Deployment actions are pinned to commit hashes, and [Dependabot](../.github/dependabot.yml) checks Actions, npm, and Bundler dependencies weekly.

## Xbox activity

The `/now/` page reads `_data/xbox.json`, an ignored file generated by `scripts/fetch-openxbl.mjs`. In development, absent live data falls back to tracked `_data/xbox_preview.yml`. Production never uses the preview; a failed refresh or missing secret leaves the card omitted on a clean CI build. Unavailable achievement data does not hide a successfully fetched profile and game.

For live activity, configure `OPENXBL_API_KEY` in GitHub Actions secrets and link the OpenXBL account to an Xbox profile with visible title history. Local development does not need the key. Run the normalization and API-handling regressions with `npm test`.

Authenticated API requests reject redirects. Errors omit response bodies and parser details to keep private data out of build logs. If the provider changes its endpoint, verify the official address before updating `API_ROOT` in `openxbl-client.mjs`. Revoke and replace any exposed key at the provider and in Actions secrets.

## Publication exclusions

`_config.yml` excludes source documentation, scripts, dependencies, demo pages, and local configuration from the site. `check-site.py` also rejects environment files, private keys, credential JSON files, and sensitive configuration directories at any depth in the generated output; failures report paths only.

Keep private files outside published content. When adding a secret filename convention, update `_config.yml`, `.gitignore`, and the artifact patterns in `check-site.py` together. Keep analytics exports and observations in ignored `.geo/`; see [search visibility operations](geo/README.md).
